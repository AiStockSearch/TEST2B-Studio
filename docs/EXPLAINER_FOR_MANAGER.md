# Как устроена мини-CRM «Объекты и задачи»

Система для строительной компании: постановщик заводит объекты (стройки) и задачи по ним, назначает исполнителя. Исполнитель берёт задачу в работу и отдаёт на проверку. Постановщик принимает работу или возвращает с замечанием. На каждом шаге фиксируется, кто и когда сменил статус.

**Роли.** Постановщик видит всё: создаёт и правит объекты и задачи, принимает или возвращает. Исполнитель видит только свои задачи и те объекты, где у него есть задачи. Чужие задачи ему недоступны.

**Статусы задачи.** Новая → В работе → На проверке → Принята. С проверки можно вернуть «На доработку» (нужен комментарий), затем снова «В работе». Других переходов нет: нельзя, например, принять задачу прямо из «Новой».

**Почему данные защищены.** Правила стоят в самой базе данных, а не только на экране. Даже если кто-то попробует обойти интерфейс и обратиться к базе напрямую, чужие задачи не прочитаются, запрещённый переход статуса не пройдёт, а журнал смен статусов нельзя подделать, изменить или удалить. Новых пользователей через форму регистрации создать нельзя — учётки заводит администратор. Секретные ключи с полными правами в приложении не используются.

**Что проверено.** Рабочий сайт и репозиторий с миграциями базы. Автотесты: таблица переходов, сценарии по ролям в интерфейсе, прямые запросы от имени исполнителя «в обход экрана» (чужое не читается и не меняется). На демо: один постановщик, два исполнителя, три объекта, задачи в разных статусах.
